ABSTRACT
DRAM–NVM hybrid memory systems address growing ca-
pacity demands by combining low-latency but capacity-limited
DRAM with high-density yet slower non-volatile memory
(NVM). Given limited DRAM capacity and NVM’s asymmet-
ric read/write costs, hybrid memory systems must select
an appropriate DRAM-resident page and demote it to NVM
while retaining hot and write-sensitive pages in DRAM. Ex-
isting heuristics typically rely on coarse access signals, while
learning-based policies can suffer from incomplete access
context, misaligned objectives, or substantial online over-
head. We proposeCAPD, an efficientContext-AwarePage-
Demotion policy that ranks DRAM-resident victim pages
using recent access context and page states. CAPD is trained
offline using replay-derived rankings based on future reuse,
write sensitivity, and demotion cost, and is invoked only at
demotion events. On PARSEC-derived traces, CAPD reduces
weighted replay cost under DRAM capacity pressure, includ-
ing a 10.83% reduction over the best classical baseline on the
streamclusterpressure window.
1 INTRODUCTION
With the growth of data-intensive applications such as ma-
chine learning [6], graph analytics [29], and in-memory an-
alytics [37], modern systems increasingly demand larger
main-memory capacity and higher memory performance.
However, DRAM scaling has become increasingly con-
strained [21], while non-volatile memory (NVM) provides
higher density and lower cost per bit [ 12, 18, 23] but suf-
fers from higher write latency [ 12, 36] and limited write
endurance [13, 39]. Therefore, DRAM–NVM hybrid memory
systems [3, 20, 24, 33], which combine low-latency DRAM
with high-density NVM, have emerged as an important main-
memory architecture.
In such systems, DRAM typically serves as a fast tier for
hot and write-sensitive pages [1, 14, 24], while NVM provides
a large-capacity tier for colder pages [ 15, 19, 25]. Because
DRAM capacity is limited, the system must demote selected
DRAM-resident pages to NVM under fast-tier pressure [11,
24, 27]. Demoting a soon-reused page can increase slow-tier
accesses and access latency [8, 16, 24], or demoting a write-
intensive page can increase NVM write traffic [14, 27] and
accelerate device wear [13, 39].
Traditional replacement policies based on fixed heuristic
rules, such as LRU, LFU, and CLOCK [ 2, 10], often strug-
gle with dynamic access behavior [ 8, 14]. Learning-based
approaches can improve adaptability by exploiting access
history [17, 26, 28, 30] and program context [7], but many tar-
get cache hit rate or prefetching [7, 9, 17, 26, 28] rather than
write sensitivity and the cost of demoting pages from DRAM
to NVM, while longer-history models may incur nontrivial
online overhead due to large history windows or complex
inference [22, 28].
To address these limitations, we present CAPD, a light-
weight context-aware page demotion policy for hybrid
DRAM–NVM memory systems. CAPD encodes recent access
records using physical addresses, program counters (PCs),
and read/write flags, then lets each DRAM candidate extract
candidate-specific context for demotion scoring.
In summary, this paper makes the following contributions:
• We formulate DRAM page demotion in hybrid mem-
ory as a cost-aware candidate-page ranking prob-
lem, enabling CAPD to select victims by comparing
DRAM-resident candidates using recent access con-
text and page-level states.
• We design a lightweight access-sequence encoder and
candidate-aware scoring mechanism that generates
demotion-priority scores from recent access context
and page-level representations.
• We construct cost-aware reference rankings with
offline replay and evaluate CAPD on real memory
traces, showing cost reductions under DRAM ca-
pacity pressure and workload-dependent boundary
cases.

write overhead: demoting soon-reused or write-intensive
pages can increase slow-tier accesses [ 16, 24] and costly
NVM writes [14, 27]. Demotion can also consume memory
bandwidth and incur page-management overhead [ 31, 34,
35]. Therefore, DRAM-to-NVM demotion in hybrid memory

2.2 Context-Aware Candidate Ranking
Traditional policies such as LRU, LFU, and CLOCK are effi-
cient, but they rely on fixed heuristics and reduce page be-
havior to simple signals such as recency or frequency [2, 10].
Two pages with similar recency or frequency can still have
very different demotion costs: one may be read-only and
cold [14], while another may be dirty, write-intensive [14],
or likely to be reused soon [16, 24]. These differences matter
in hybrid memory systems because write behavior and de-
motion cost directly affect the benefit of keeping a page in
DRAM [14, 16].
Learning-based policies can use access history to improve
adaptivity [17, 28, 30], but they must remain lightweight
enough for demotion-time decisions. Modeling long histories
or scoring each candidate against the full access sequence
can introduce nontrivial online overhead [17, 22, 28]. At the
same time, using only address sequences may miss useful
signals from the program counter [ 7, 32] and read/write
type [14].
These observations motivate a lightweight context-aware
ranking formulation: at each demotion point, the policy
should use recent access context and page-level states to
rank the current DRAM candidates and demote the page
with the highest demotion priority. CAPD follows this direc-
tion by learning a cost-aware candidate-page ranking policy
for DRAM-to-NVM demotion.
3 DESIGN
3.1 Overall Framework
Figure 1 illustrates the overall framework of CAPD. CAPD
treats DRAM page demotion as a context-aware candidate
ranking problem. It consists of four components: Multi-
dimensional Feature Construction, Lightweight Access Se-
quence Encoding, Candidate-Aware Context Scoring and
Demotion Decision, and Cost-Aware Ranking Optimization.
It encodes recent accesses with a lightweight Transformer,
lets each candidate page query the encoded sequence to
obtain a candidate-specific context, and scores the context
for demotion. Training uses offline trace replay to derive a
cost-aware ranking objective.

4 EV ALUATION
4.1 Experimental Setup
We evaluate CAPD using trace replay on PARSEC-derived
memory traces. We collect user-space memory references
with DynamoRIO/drmemtrace and convert the drmemtrace
view output into PC,Address,RW records. The recorded ad-
dresses are virtual addresses from the traced process. We
align each address to a 4KB page with page_shift=12 and
use the resulting virtual page identifier in replay; the proto-
type does not reconstruct physical addresses.
For the standard 1M-trace experiments, each workload
contains 1,000,000 memory references and is split chrono-
logically into 800K training, 100K validation, and 100K test
references. All reported standard-split results use the held-
out test window. For pressure-window experiments, we se-
lect test windows before CAPD evaluation using only LRU
replacement pressure under a 16-page DRAM, not CAPD
performance. The selected streamcluster pressure window
uses references 0–270K for training, 270K–370K for valida-
tion, and 370K–570K for testing. The selected dedup pressure
window uses references 0–700K for training, 700K–800K for
validation, and 800K–1M for testing.
Unless otherwise stated, the DRAM tier holds 16 pages, the
history window contains 10 accesses, the eviction candidate
set contains 8 pages, and the prediction lookahead is 256
accesses. At each DRAM miss with a full DRAM tier, the
candidate set is constructed from the 8 pages at the LRU tail
of the current DRAM-resident set.
CAPD uses 8-dimensional page-address embeddings, 8-
dimensional PC embeddings, and 2-dimensional read/write
embeddings, giving an 18-dimensional access representa-
tion. The sequence encoder is a one-layer Transformer with
2 attention heads and a 72-dimensional feed-forward layer.
Each candidate page is represented by an 8-dimensional page
embedding and four state features: recent frequency, dirty
status, normalized residency duration, and normalized LRU-
tail rank. The candidate scorer uses 2-head cross-attention
from candidate pages to the encoded access sequence, fol-
lowed by an MLP with hidden dimensions 36 and 18. We
train for 10 epochs with batch size 32.
We compare CAPD against four classical replacement
policies, LRU, Random, LFU, and CLOCK, and two learned
trace-replay baselines. Kleio-lite follows Kleio’s neural page-
hotness prediction and page-prioritization logic [4]. PatternS-
lite follows PatternS’s page-pattern clustering and group-
level hotness-prediction logic [ 38]. These baselines are
replay-compatible adaptations rather than full-system re-
productions.
We use a weighted cost metric:
𝐶=𝑁 hit +2𝑁 nvm_read +8𝑁 nvm_write +10𝑁 demotion.
This metric charges NVM writes and demotions more heavily
than DRAM hits, matching the asymmetric cost structure of
hybrid DRAM–NVM memory. Lower cost is better.
Unless otherwise stated, Figure??and Table 1 report the
result of a pre-specified default training seed, 3136859. This
seed was fixed before inspecting the test results and is used
consistently for the main replay comparison. Section ?? sep-
arately reports three-seed stability results to show which
conclusions are robust to training randomness.
4.2 Main Results
Figure 2 summarizes the main replay results. CAPD improves
the weighted cost on workloads where replacement decisions
expose a real tradeoff between hit rate, writes, and demotions.
On streamcluster-pressure, CAPD reduces normalized cost
by 10.83% over the best classical baseline and by 18.93% over
the best learned baseline. On blackscholes, the default-seed
run slightly improves over the best baseline, but Section ??
shows that this small gain is seed-sensitive. We therefore
treat blackscholes as a near-tie rather than as primary evi-
dence for CAPD’s benefit.

4.3 Capacity Sensitivity
We next vary the DRAM capacity on streamcluster-pressure,
the workload with the clearest memory-pressure behavior.
This experiment tests whether CAPD only wins at a single
cache size or remains useful across pressure levels.
Table 2 shows that CAPD is most useful when DRAM
pressure is high. With 8 and 16 DRAM pages, it reduces
weighted cost by about 10% relative to the best rule-based
policy. With 32 pages, the miss stream shrinks substantially
and replacement decisions become less consequential; CAPD
then converges to near parity with the best classical baseline.
This behavior is expected for a learned eviction policy: its
advantage appears when the cache is small enough that
choosing the wrong victim causes repeated NVM accesses
or demotions.
4.4 Stability and Robustness
Because CAPD is trained, we check whether the main re-
sult depends on a single training seed. The main Figure ??
andTable 1 use the pre-specified default seed 3136859. We
then retrain CAPD with seeds 3136859, 42, and 2026 while
reusing the same deterministic rule-based baselines.
On streamcluster-pressure, all three seeds beat the best
classical baseline: the cost reduction ranges from 10.69% to
11.71%, with mean 11.08% and standard deviation 0.45%. This
supports streamcluster-pressure as the main positive result.
On blackscholes, the default seed improves cost by 0.91%,
but the three-seed mean is +0.24% with standard deviation
1.71%; one seed is 2.66% worse than LFU. We therefore inter-
pret blackscholes as a near-tie rather than a robust win. On
canneal, all three seeds are worse than LRU, with mean delta
+16.81%, confirming it as a stable negative boundary case.
We also reweight the dominant pressure case under al-
ternative cost models. On streamcluster-pressure, CAPD
remains better than the best classical baseline under mild,
write-heavy, and demotion-heavy cost settings, with reduc-
tions from 6.98% to 15.91%. This suggests that the result is
not an artifact of a single hand-picked write or demotion
weight.
4.5 Discussion
The results support two observations. First, the com-
plete CAPD framework can improve DRAM-to-NVM de-
motion decisions under sustained capacity pressure. On
streamcluster-pressure, CAPD improves the hit rate
while reducing NVM reads, NVM writes, and demotions,
and its weighted-cost reduction remains stable across train-
ing seeds and alternative cost settings.
Second, CAPD’s benefit is workload-dependent. CAPD
remains near parity with the strongest baselines on
blackscholes and dedup-pressure, while on canneal it
increases weighted replay cost by 15.32% relative to the best
classical baseline. This negative case shows that the learned
ranking policy does not uniformly outperform classical poli-
cies across all trace regimes. Overall, the results suggest that
context-aware candidate ranking is most useful when demo-
tion choices materially affect future slow-tier accesses and
page-movement cost.
5 CONCLUSION
This paper presented CAPD, a context-aware page-demotion
policy for DRAM–NVM hybrid memory systems. CAPD for-
mulates DRAM victim selection as a candidate-page ranking
problem: it encodes recent memory accesses and uses each
candidate’s page representation to derive candidate-specific
context for demotion scoring. Offline trace replay provides
cost-aware reference rankings, while online inference is in-
voked only when DRAM capacity pressure triggers a demo-
tion event. On PARSEC-derived traces, CAPD achieves its
clearest benefit under sustained pressure, reducing weighted
replay cost by 10.83% on streamcluster-pressure. It re-
mains near parity on blackscholes and dedup-pressure,
but underperforms on canneal, demonstrating that its ben-
efit is workload-dependent. These results establish context-
aware candidate ranking as a promising direction for DRAM-
to-NVM demotion while motivating broader workload eval-
uation and runtime integration.
